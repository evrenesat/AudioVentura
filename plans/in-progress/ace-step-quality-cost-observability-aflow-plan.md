## Current Evidence and Diagnosis

1. The worker already uses the larger `acestep-v15-xl-turbo` DiT; this is not a small-generator deployment mistake.
2. Originals use `acestep-5Hz-lm-1.7B`. Covers skip the LM, so a larger LM cannot improve covers.
3. `runpod_worker/handler.py` sends `audio_cover_strength` but omits ACE-Step v0.1.8's independent `cover_noise_strength`. It therefore uses default 0.0, the least melody-retaining behavior.
4. Pinned ACE-Step v0.1.8 fixes cover output duration to the source waveform. The beta must show and retain that detected duration; “longer remix” remains a deferred enhancement rather than an ignored promise.
5. Original duration written only in the description is not mapped to the duration field. The observed “about 6 minutes” job sent `duration=-1` and produced roughly 3.5 minutes.
6. Jobs persist queue/execution time and GPU/model, but no immutable price or attributable cost.
7. At the observed USD 0.49/L4-hour, execution-only estimates are about USD 0.0031 for the 22.499-second cover and USD 0.0057 for the 42.026-second original. They are not invoice charges.
8. AudioVentura accepts captions/lyrics far beyond upstream's documented 512/4096-character bounds, fixes one cover candidate, and drops effective planner metadata, making weak results harder to prevent or explain.
9. `use_format=True` is silently discarded because pinned v0.1.8 `GenerationParams` has no such field.
10. The controller and worker both enforce strict schema version 1 payloads. Adding quality fields without an explicit version transition would strand persisted/queued jobs or break rollback.
11. SQLite startup uses `Base.metadata.create_all()`, which cannot alter existing tables. Durable cost columns require a real, versioned migration path rather than an ORM-model-only change.

## Critical Invariants

- Runpod workers minimum zero, maximum one; application generation concurrency one.
- No long-lived Runpod, transfer-service, home-ingest, registry, or Tailscale credential reaches browsers, logs, Git, metadata, or URLs. The only URL bearer is an expiring, single-purpose transfer capability passed server-to-server; redact it from logs and never persist it in request/result metadata.
- Public UI remains authenticated HTTPS. Controller and transfer processes bind loopback behind the HTTPS edge; only the narrowly scoped capability transfer routes are reachable by Runpod. Home ingest remains Tailscale-only.
- Signed, expiring, single-purpose transfer capabilities remain intact and are consumed/revoked according to the existing transfer contract.
- The controller never invokes media binaries. Quality evaluation uses the existing durable controller queue and signed-transfer path; it must not bypass orchestration or call ACE-Step directly.
- Store timestamps UTC. Aggregate UI days with configurable IANA `USAGE_TIMEZONE`; deploy `Europe/Amsterdam`.
- Store USD amounts as integer micro-USD and preserve provider/rate inputs as validated fixed-decimal strings, never binary float. Parse JSON monetary numbers directly as decimal text. For an hourly USD rate, compute `round_half_up(execution_ms × hourly_rate_usd × 1_000_000 / 3_600_000)`; do not first round to a per-second rate.
- Keep the pre-submit quote snapshot separate from the executed-attempt rate snapshot. Never overwrite either or recalculate history from the current catalog.
- Queue delay is not compute. Per-job `execution_ms × GPU rate` is “estimated attributable compute,” not “actual.”
- Preserve Runpod billing records in their native UTC bucket boundaries with source identifiers, fetch time, and raw amount. Derive local-day views from explicit UTC intervals; do not relabel vendor UTC day buckets as Amsterdam days.
- Represent application time windows as half-open UTC intervals `[start, end)`. Validate Runpod's `startTime`/`endTime` boundary behavior with fixtures and one read-only live probe before enabling billing UI; if exact inclusion semantics cannot be established, mark provider totals unavailable rather than risk gaps or double counting.
- Endpoint billing includes worker initialization, execution, idle time, and billing rounding. Show the signed difference from summed attempt estimates as “unattributed reconciliation delta,” not as a proven startup/idle charge.
- Show network-volume/container-storage spend separately; never allocate it arbitrarily to a song.
- Billing and pricing credentials remain server-side. Prompts, lyrics, source URLs, private evaluation media, and listener identities stay out of logs and billing records.
- Production migrations are ordered, additive, and old-release-readable: no table rebuild/drop, destructive backfill, or new non-null column without a safe default.
- Required pinned ACE parameters must fail closed if absent; do not silently signature-filter them.
- Published profile IDs are immutable. A measured winner whose resolved parameters differ from an existing profile receives a new versioned ID; promotion changes only the default-profile reference.
